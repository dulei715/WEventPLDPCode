# PLDP-IDS: Personalized Local Differential Privacy for Infinite Data Stream

This repository contains the implementation and experiment scripts for PLDP-IDS. The complete technical report, including the extended proofs, algorithm details, and additional experiments, is available at [arXiv:2611.11467](https://arxiv.org/abs/2611.11467).

The main methods include LPD/LPA, Direct-PLPD/Direct-PLPA, Basic-PLPD/Basic-PLPA, GA-OPS-only and BA-PUE-only ablations, and the enhanced PLPD+/PLPA+ methods with Pre and Post fusion modes.

# Environment and Build

## Requirements

* Linux, macOS, or another environment with Bash and standard shell utilities.
* JDK 8 and Maven for compiling the Java implementation.
* MATLAB 2017a or a compatible MATLAB version for the MATLAB plotting scripts.
* Python 3 and `matplotlib>=3.5.0` for the Python plotting scripts.
* The experiments may require a large amount of memory. Adjust the JVM options in the deployment scripts according to the available machine resources.

## Build

1. Direct to ${project_path}.
2. Run `mvn package`.
3. The assembly plugin writes `WEventPLDPCode-1.0-SNAPSHOT-jar-with-dependencies.jar` to ${project_path}/deployment.
4. Copy the files in `deployment` to `${basic_path}/deployment`, where `${basic_path}` is any fixed path selected by the user.
5. Direct to ${basic_path}/deployment before running the shell scripts. The scripts use relative paths such as `../0.dataset` and the jar in the current directory.

All ${xxx} variables in this README are user-defined placeholders. Replace them with paths on your own machine; no machine-specific path is required by the repository.

# Data Sets

## Real data set links

*Taxi* Data set (T-Drive trajectory data sample): [https://www.microsoft.com/en-us/research/publication/t-drive-trajectory-data-sample/](https://www.microsoft.com/en-us/research/publication/t-drive-trajectory-data-sample/).

*Foursquare* Data set (Global-scale Check-in Dataset): [https://sites.google.com/site/yangdingqi/home/foursquare-dataset](https://sites.google.com/site/yangdingqi/home/foursquare-dataset).

The use of downloaded data must follow the terms provided by the original data source.

## Data set summary

* *Taxi*: 10,269 taxis and 14,859,377 valid records after cleaning; locations are mapped to `d=5` areas and sampled every minute, resulting in `T=8,889` time slots.
* *Foursquare*: 33,278,683 check-ins from 266,909 users; venues are mapped to `d=5` categories and grouped into 100-minute slots, resulting in `n=13,216` user streams and `T=7,649` time slots.

## Synthetic data sets

`TLNS`, `Sin`, and `Log` are generated by the Java implementation and do not require external downloads. The default experiment uses `n=10000`, `T=10000`, and domain size `d=5`.

* `TLNS`: clipped random walk with `p_0=0.05` and `Q=0.0025`.
* `Sin`: `p_t=0.05 sin(0.01t)+0.5`.
* `Log`: `p_t=0.7/(1+exp(-0.02t))`.

At each time slot, the designated status has probability `p_t`; the remaining probability mass is distributed uniformly over the other `d-1` statuses.

# Run Process

## Configuration and paths

1. Create paths ${basic_path}/0.dataset/${dataset_name}, where ${dataset_name} is one of `T-drive_Taxi_Trajectories`, `CheckIn_dataset_TIST2015`, `TLNS`, `Sin`, or `Log`.
2. Download and extract the *Taxi* and *Foursquare* data sets into ${basic_path}/0.dataset/T-drive_Taxi_Trajectories and ${basic_path}/0.dataset/CheckIn_dataset_TIST2015, respectively.
3. Check the dataset names, file names, and experiment parameters in ${basic_path}/deployment/config/parameter_config.xml.
4. For real data sets, confirm the input files expected by the configuration before running the initialization scripts. The pre-processing stage creates the files used by the main runs, including the location/status index files.

## Build and pre-process

1. Direct to ${basic_path}/deployment.
2. Run `bash _0_initialize_scripts/initialize_trajectory_run.sh` for *Taxi*.
3. Run `bash _0_initialize_scripts/initialize_check_in_run.sh` for *Foursquare*.

The synthetic data sets are generated by their main run scripts, so no separate download or initialization step is required for `TLNS`, `Sin`, or `Log`.

## Repeat run for real data sets

The default scripts repeat each experiment for ten random seeds (`0` through `9`).

* Run for *Taxi*:
	* `bash _1_main_run_scripts/trajectory_main_repeat_run.sh`
* Run for *Foursquare*:
	* `bash _1_main_run_scripts/checkIn_main_repeat_run.sh`

## Repeat run for synthetic data sets

* Run for *TLNS*:
	* `bash _1_main_run_scripts/tlns_main_repeat_run.sh`
* Run for *Sin*:
	* `bash _1_main_run_scripts/sin_main_repeat_run.sh`
* Run for *Log*:
	* `bash _1_main_run_scripts/log_main_repeat_run.sh`

The main run scripts accept an optional second argument `serial`. For example:

```bash
bash _1_main_run_scripts/sin_main_repeat_run.sh serial
```

Without this argument the data-set runs use the parallel execution path. The serial path is intended for comparable time-cost measurements. Keep the run mode consistent with the post-processing directory that is being combined.

## Main experiment settings

The default settings follow the paper:

* Global privacy budget: `epsilon = 0.5, 1.0, 1.5, 2.0, 2.5`.
* Global window size: `w = 40, 80, 120, 160, 200`.
* Default values: `epsilon = 1.5` and `w = 120`.
* Population lower bound: `u_min = 10`.
* Eigenvalue clipping lower bound: `mu = 1e-6`.
* Each setting is repeated ten times with random seeds `0` through `9`, and the reported result is the average.

When changing the number of repeated rounds, update `combineRound` in `parameter_config.xml` or use the supported repeat-round override in the corresponding post-processing command. The number of rounds used by combination must match the rounds that actually exist.

## Domain-size experiment

The domain-size scripts evaluate `d = 2, 5, 10, 25, 50` for `TLNS`, `Sin`, and `Log`.

* Run for *TLNS*:
	* `bash _4_domain_size_scripts/tlns_domain_size_run.sh`
* Run for *Sin*:
	* `bash _4_domain_size_scripts/sin_domain_size_run.sh`
* Run for *Log*:
	* `bash _4_domain_size_scripts/log_domain_size_run.sh`

These scripts use the `fixed` experiment tag and write results to ${basic_path}/2.domain_change_ldp_result. The domain list and fixed experiment parameters can be changed in `parameter_config.xml`.

## Privacy-data correlation experiment

The group-shift experiment uses the `Sin` data set and evaluates both `positive` and `reverse` shifts.

1. Run the experiment:
	* `bash _1_main_run_scripts/sin_group_shift_run.sh`
2. Aggregate the per-round metrics:
	* `bash _2_combine_scripts/aggregate_group_shift_metrics.sh ../3.group_shift_ldp_result`
3. Plot the aggregated metrics after installing the Python requirements:

```bash
python3 _2_combine_scripts/plot_group_shift_metrics.py \
  --summary ../3.group_shift_ldp_result/aggregated/group_shift_paper_summary.csv \
  --output-dir ${output_basic_path}/figures/experiment_result_add/group_shift
```

The default shift values are `0`, `0.05`, `0.10`, `0.15`, and `0.20`. The group ratios, budgets, window sizes, and offset scales are configured in `parameter_config.xml` and can be overridden by the environment variables documented in `sin_group_shift_run.sh`.

## User-scaled probe

`_4_domain_size_scripts/user_scaled_probe.sh` is an optional diagnostic experiment for checking whether increasing the user population with the domain size changes the method ranking. Its defaults can be overridden with the `PROBE_*` environment variables defined in the script.

# Draw Results

## Initialize MATLAB (2017a)

1. Direct to ${project_path}/matlab_code/experiment_result.
2. Run function `init_params()`.
3. Create directories ${output_basic_path}/figures/experiment_result and ${output_basic_path}/figures/experiment_result_add.

## Plot Results with MATLAB

* Run function `bar_main()` to export the main-method legend figure.
* Run function `bar_ablation()` to export the ablation-method legend figure.
* Run function `b_3_plotMainBudgetChangeForError(${basic_path}/1.main_ldp_result,${output_basic_path})`.
* Run function `b_4_plotMainWindowSizeChangeForError(${basic_path}/1.main_ldp_result,${output_basic_path})`.
* Run function `c_1_plotAblationBudgetChangeForError(${basic_path}/1.main_ldp_result,${output_basic_path})`.
* Run function `c_2_plotAblationWindowSizeChangeForError(${basic_path}/1.main_ldp_result,${output_basic_path})`.
* Run function `b_1_plotBudgetChangeForTime(${basic_path}/1.main_ldp_result,${output_basic_path})`.
* Run function `b_2_plotWindowSizeChangeForTime(${basic_path}/1.main_ldp_result,${output_basic_path})`

The MATLAB scripts report AMSE and AJSD for utility and running time for computational cost. Lower values indicate better utility or lower cost.

## Plot Results with Python

1. Direct to ${project_path}/python_code.
2. Install the plotting dependency:

```bash
python3 -m pip install -r requirements.txt
```

3. Plot the main and ablation experiments:

```bash
python3 run_all.py \
  --input-basic-path ${basic_path}/1.main_ldp_result \
  --output-basic-path ${output_basic_path} \
  --tasks all
```

4. Plot the domain-size experiment:

```bash
python3 run_all.py \
  --domain-input-path ${basic_path}/2.domain_change_ldp_result \
  --output-basic-path ${output_basic_path} \
  --tasks b5,b6
```

5. Plot the group-shift experiment:

```bash
python3 run_all.py \
  --shift-input-path ${basic_path}/3.group_shift_ldp_result \
  --output-basic-path ${output_basic_path} \
  --tasks s1
```

Use `--check-names` to verify that the method names in `result.txt` match the plotting configuration before exporting figures. MATLAB and Python read the same combined result directories; use either plotting workflow according to the desired output format.

# Reproduction Notes

* The paper evaluates LPD/LPA, Direct-PLPD/Direct-PLPA, Basic-PLPD/Basic-PLPA, GA-OPS-only, BA-PUE-only, and PLPD+/PLPA+ with Pre and Post modes.
* The main utility metrics are AMSE and AJSD. The plotting scripts use the natural logarithm of these metrics for readability.
* The enhanced PLPA+ method is expected to outperform the direct personalized baseline on the paper's real and synthetic data sets. The complete report gives the detailed numerical comparisons and additional ablation results.
* The scripts under `_3_copy_result_to_git` are deployment-specific helper scripts and may require extra server-side environment variables. They are not required for reproducing the main experiments.
